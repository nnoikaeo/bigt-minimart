## การตัดสินใจ

- **หน้า Auditor ของ BP ยึดรูปแบบ MT** ตามที่ Owner ขอ: การ์ดยอดเงิน, ตัดตาราง Step 1/2 แยก, ช่องรายละเอียดช่องเดียว, ปุ่มและกล่องยืนยัน, ผลตรวจเป็นกล่องพับได้
- **ใช้ placeholder แทนเลข 0 ทุกหน้า** ตามที่ Owner ขอ ยกเว้นตารางค่าธรรมเนียมในหน้าตั้งค่า เพราะ 0 เป็นค่าจริงที่บันทึกไว้

ผมตัดสินใจเองระหว่างทำงาน และยังเปลี่ยนได้:

- ปุ่ม "ส่งคืนแก้ไข" ของ BP ต้องกรอกรายละเอียดก่อน แต่ไม่ต้องกรอกยอดนับ
- BP แสดงหมายเหตุ Manager ให้ Auditor เห็น (MT ไม่แสดง)
- ปุ่มเขียวของ BP เข้มกว่า MT — ต้องตัดสินใจตอน MT-3 ว่าจะให้ MT เหมือน BP หรือไม่
- ยอดตั้งต้นแบบกำหนดเองต้องกรอกก่อนยืนยัน (ตั้งเป็นศูนย์ให้พิมพ์ 0)

## บทเรียน

- **Test ผ่านไม่ได้แปลว่าหน้าจอใช้ได้:** BUG-021 ไม่ถูกจับเพราะข้อมูลทดสอบกรอกยอดไว้ก่อนแล้ว และ BUG-023 ไม่ถูกจับเพราะ integration test ใช้ server จำลอง จึงเพิ่ม test ที่เรียกโค้ด repository จริง
- **ปุ่มที่ต่างกันต้องดูต่างกันชัดเจน:** ในรอบ B มีการกดปุ่มเขียวแทนปุ่มหมายเหตุ ทำให้ต้องทดสอบกรณีนี้ซ้ำกับวันที่อื่น กล่องยืนยันในภาพเป็นตัวบอกว่ากดปุ่มไหนไปจริง
- **ส่งภาพเห็นจุดที่ต้องตรวจเสมอ:** ถ้าภาพไม่ครอบคลุม เช่น เปิดหน้าแต่ไม่ได้เปิดฟอร์ม ให้นับว่ายังไม่ได้ทดสอบ
- **`npm run lint` ตรวจไฟล์ test ด้วย:** spec ใหม่ต้องมี `// @ts-nocheck` เหมือนไฟล์อื่น หรือ import จาก vitest ตรง ๆ
