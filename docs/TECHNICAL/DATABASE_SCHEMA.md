# 🗄️ Database Schema (Firestore)

> ⚠️ **Status (Oct 2026)**: This is the **target Firestore schema** from the v1.0 spec (Jan 2026).
> Firestore is not in use yet — all data lives in JSON files under `public/data/`.
> The source of truth for current data shapes is the TypeScript types:
>
> | Domain | Types | JSON files |
> |--------|-------|------------|
> | Users / roles | `types/user.ts`, `types/permissions.ts`, `types/access-control.ts` | `users.json`, `roles.json`, `permissions.json`, `role-permissions.json`, `sidebar-menu.json` |
> | Daily Sales | `types/repositories.ts` (`DailySalesEntry`) | `daily-sales.json` |
> | Money Transfer | `types/repositories.ts` (`MoneyTransferTransaction`, …) | `money-transfer-{transactions,balances,summaries,favorites,fee-config}.json` |
> | Bill Payment | `types/bill-payment.ts` | `bill-payment-{transactions,balances,summaries,favorites,fee-config}.json` |
> | Shared workflow statuses | `types/shared-workflow.ts` | — |
>
> Money Transfer and Bill Payment collections are not described below; add them here when the
> Firestore migration is planned.

## Collections Overview

### Collection: users
User accounts and roles

```typescript
interface User {
  uid: string;                    // Firebase Auth UID
  email: string;                  // Email address
  displayName: string;            // Display name
  role: UserRole;                 // Role/permission level
  posNumber: 1 | 2 | null;       // POS assignment
  isActive: boolean;              // Active status
  createdAt: Timestamp;
  updatedAt: Timestamp;
  createdBy?: string;             // Creator UID
}

type UserRole = 
  | "owner"              // Owner
  | "manager"            // Manager
  | "assistant_manager"  // Assistant Manager
  | "cashier"            // Cashier
  | "auditor";           // Auditor
```

**Indexes**:
- email (Unique)
- role + isActive (Composite)

### Collection: daily_sales
Daily sales records - บันทึกยอดขายรายวัน (Auditor บันทึก)

```typescript
interface DailySales {
  // Identification
  id: string;                              // Auto-generated by Firestore
  date: Timestamp;                         // วันที่บันทึก
  
  // Cashier Information
  cashierId: string;                       // Firebase UID ของแคชเชียร์
  cashierName: string;                     // ชื่อแคชเชียร์
  
  // Sales Data (from POSPOS Receipt - Auditor บันทึก)
  posposData: {
    cashAmount: number;                    // เงินสด (Cash)
    qrCode: number;                        // ยอดขาย QR Code
    bankTransfer: number;                  // ยอดขาย ธนาคาร (Bank)
    govProgram: number;                    // ยอดขาย โครงการรัฐ (Government)
    totalSales: number;                    // รวมยอดขายทั้งหมด (AUTO CALC)
  };
  
  // Cash Reconciliation (ผลต่างเงินสด)
  cashReconciliation: {
    expectedAmount: number;                // เงินคาดไว้จาก POSPOS
    initialBalance: number;                // เงินเริ่มต้น 2,000 บาท
    actualCashInDrawer: number;            // เงินจริงที่นับได้
    difference: number;                    // ผลต่าง = actualCashInDrawer - expectedAmount (AUTO)
    notes?: string;                        // หมายเหตุ (ถ้าผลต่าง ≠ 0)
  };
  
  // Status & Workflow
  status: SalesStatus;                     // Current status
  submittedAt: Timestamp;                  // เมื่อ Auditor บันทึก
  submittedBy: string;                     // Auditor UID
  
  auditedAt?: Timestamp;                   // เมื่อ Auditor ตรวจสอบ (Week 4)
  auditedBy?: string;                      // Auditor UID
  auditNotes?: string;                     // หมายเหตุจาก Auditor
  
  // System Timestamps
  createdAt: Timestamp;                    // Created timestamp
  updatedAt: Timestamp;                    // Last update timestamp
}

type SalesStatus = "submitted" | "audited" | "approved";
```

**Workflow**:
1. `submitted` - Auditor บันทึกข้อมูล (Task 3.1)
2. `audited` - Auditor ตรวจสอบเสร็จแล้ว (Week 4)
3. `approved` - Manager อนุมัติ (Week 4+)

**Indexes**:
- `date` (Ascending) - สำหรับ filter by date
- `date + status` (Composite) - สำหรับ filter by date + status
- `cashierId + date` (Composite) - สำหรับ filter by cashier
- `status` (Ascending) - สำหรับ filter by status

**Security Rules**:
- Auditor: Can read/write own submissions
- Manager: Can read all, approve submissions
- Owner: Can read all, manage data

## Collection: role_permissions
Role-based page access control configuration - กำหนดสิทธิ์การเข้าถึง pages ของแต่ละ role

```typescript
interface RolePermissions {
  // Identification
  role: UserRole;                    // "owner" | "manager" | "auditor" | "cashier" | "staff"
  name: string;                      // Thai name (ผู้จัดการร้าน, ผู้ตรวจสอบ, etc.)
  description?: string;              // Description of role
  
  // Page Access Matrix
  pages: Record<string, boolean>;    // {
                                     //   "sales/daily-sales": true,
                                     //   "sales/sales-report": false,
                                     //   "finance/daily-expenses": true,
                                     //   ...
                                     // }
  
  // System Fields
  updatedAt: Timestamp;              // Last update
  updatedBy: string;                 // Admin UID who made changes
}
```

**Design Notes**:
- **Owner**: Auto-access all pages (empty `pages` object means all)
- **Other roles**: Explicit page access matrix
- **Pages**: Use full route path (e.g., "sales/daily-sales")

**Example Data**:
```firestore

  "pages": {

  "updatedBy": "owner-uid-1"
}

// manager document
{
  "role": "manager",
  "name": "ผู้จัดการร้าน",
  "description": "จัดการปฏิบัติการรายวัน",
  "pages": {
    "sales/daily-sales": false,
    "sales/sales-report": true,
    "finance/daily-expenses": true,
    "finance/cash-flow": true,
    "finance/monthly-report": false,
    "hr/attendance": true,
    "hr/overtime": true,
    "settings/system-settings": false,
    "settings/others": false,
    "admin/users": false,
    "admin/roles": false
  },
  "updatedAt": Timestamp,
  "updatedBy": "owner-uid-1"

// owner document (implicit - no need to store)
// owner auto-access all pages
```

**Validation Rules**:
- Owner: Must have access to all pages (non-negotiable)
- No role should have more access than owner
- Admin-only pages (admin/users, admin/roles): Only owner
- Page routes must match actual application routes

**Indexes**:
- `role` (Unique) - Single document per role

**Security Rules**:
- Public: Read (for client-side filtering)
- Admin only: Write/Update (owner can manage roles)
