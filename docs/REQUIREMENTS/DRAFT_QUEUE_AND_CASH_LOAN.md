## 2. การทำงานจริงที่ร้าน (จาก Owner)

1. **โอนเงิน เงินในบัญชีไม่พอ** — บันทึกรายการชั่วคราว → โทรหา Owner → Owner โอนเงินเข้าบัญชี → พนักงานโอนในแอปธนาคาร
2. **ลูกค้ามาพร้อมกันหลายคน** — บันทึกทุกรายการก่อน (เหมือนคิว) → ทำในแอปธนาคารทีละรายการ → เงินหมดกลางคัน → โทรหา Owner ให้โอนเพิ่ม → ทำต่อ (มีรายการค้างพร้อมกันหลายรายการได้)
3. **ถอนเงินยอดเล็กตอนเพิ่งเปิดร้าน** — เงินสดจากบริการโอนยังไม่พอ → **ยืมเงินสดจากเงินขายสินค้า**มาจ่ายก่อน (เงินออกไปจริงแล้ว)

## 4. PR 1 — คิว Draft (MT + BP)

### Flow
```
บันทึกรายการ (โอน/ถอน) → draft (ไม่นับยอด) → บันทึกรายการถัดไปได้
   ↓ ทำในแอปธนาคาร
กด "ดำเนินการ" ที่ draft
   ├─ ยอดพอ            → completed (นับยอด)
   ├─ โอน: บัญชีไม่พอ     → แจ้ง "ยอดในบัญชีไม่พอ — โทรหา Owner ให้ฝากเงินเข้า"
   ├─ ถอน: เงินสดไม่พอ    → ปุ่ม [ยืมเงินขาย X ฿ แล้วดำเนินการ] (PR 2; ใน PR 1 = แจ้งยอดไม่พอ)
   └─ แอปธนาคารไม่ผ่าน   → "ยกเลิก" (cancelled, ไม่กระทบยอด)
```

### งาน
- Server `POST /api/money-transfer/transactions`: โอน/ถอน → `draft` เสมอ; `owner_deposit` → `completed`
- ฟอร์ม `TransactionForm.vue`: ตัดตัวเลือก "สำเร็จ / ไม่สำเร็จ" ตอนสร้างใหม่; banner เปลี่ยนเป็นข้อมูลยอด (ไม่ใช่การตัดสิน)
- รายการโปรด: ใช้เส้นทางเดียวกัน (ไม่มีการตัดสิน draft ฝั่ง client)
- Draft: เพิ่มการ "ยกเลิก" draft (แอปธนาคารไม่ผ่าน) — ปัจจุบันมีแค่ ดำเนินการ / ลบ
- **BUG-004:** `complete.post.ts` เช็ค `transferCash` สำหรับถอนเงิน (ไม่ใช่ `bankAccount` เสมอ)
- BP: ทำแบบเดียวกัน (ตรวจ `stores/bill-payment.ts` + `server/api/bill-payment/` ก่อน — ชื่อ method ต่างจาก MT)
- Tab "รอดำเนินการ" = คิวงาน (มีอยู่แล้ว)
